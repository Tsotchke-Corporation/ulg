## Mission context

The campaign goal is the adaptive-laws architecture: hundreds of thousands
of particles in real time on a bulk MLS-MPM-speed substrate, with laws
(thermal, chemistry, contact consequences) invoked only where conditions
demand, across all SS-tree scales. The user's real-time definition:
`steps/s × dt ≥ 1` AND ≥60 distinct states/s reaching the eye. Reference
point: modified WebGPU-Ocean does 100k @ 120fps on the same class of GPU.

### 3. THE root cause: V1→V2 directory consumer migration (`6bac50e`)
Canonical mechanics were a silent whole-step rollback for every
V2-directory scene: the authority gate rejected each step and
`finalize_canonical_spatial_authority` restored all particles while
commits/seals/sim-time advanced normally. Three seams, each alone
sufficient:
- consumers pinned directory header version 1, producers stamp 2;
- V2 reverse map encodes `cell_index + 1` (0 = dormant), consumers
  decoded raw;
- query profile written at `particle_to_cell + capacity`, read at
  `+ live` (now `word47 − 6`, valid for both layouts) — plus the host
  exact-near gate still excluding GPU-authored counts.

Consequences: **every canonical rate measured before this fix (night-1
curve, burst A/Bs) was rolled-back frozen mechanics and must be
re-measured.** Post-fix canonical at 4k: ~126–150 steps/s.
`?observeSpatialAuthority=1` is the permanent instrument (per-step
rejection counters, header dump, query words, sampled row); it is a burst
blocker (per-step mapAsync).

### 5. User-reported slideshow: four stacked presentation bugs (Aug 28)
All four were real; the user's reports drove each find.
- **Hash rewrite dropped runtime knobs** (`5f9617f`): any control edit
  rewrote the hash to `scenario=custom`, silently dropping every
  runtime-only preset key (workerLivePreview, compactMechanicsView,
  submitBurstSteps, ambientPressurePa, contact tuning). Knobs now ride
  the canonical hash; preset resolution falls back to the query scenario.
- **Rebuild epoch pinning** (`7bf87fa`): after any control-edit rebuild
  the presentation worker restarted its candidate-stream epoch at 1 while
  the bridge kept the retired lane's stream identity → every committed
  presentation silently rejected → the page burned its full 15 s
  committed-presentation wait per schedule (~4 steps/s at 4k vs ~130
  fresh). Worker epochs now monotonic across re-inits; bridge resets its
  stream mirror when a fresh worker attaches. Diagnostic ring
  `globalThis.__ulgCommittedPresentationReceiptTrace` records every
  committed-claiming receipt evaluation with the failing conjunct.
- **Live preview was never visible** (`b804989`, user-proven): preview
  draws landed on a `visibility:hidden` worker canvas; three
  live-preview-unaware paths (render display-owner selection,
  post-first-frame native handoff, resident-render suppress branch) kept
  resetting the bridge's content-ready latch, and previews are barred
  from revealing pixels. All three now pin worker display ownership while
  a preview is requested and the lane is live
  (`scene.userData.sphWorkerLaneLivePreviewRequested`).
- **Ghost surface + input latency** (`f59c38e`): the worker canvas
  cleared transparent, compositing live particles over the STALE
  committed isosurface beneath ("debug particles never cleared") —
  preview draws now clear opaque. Candidate draws used the
  view-projection frozen at schedule submission — camera drags lagged by
  up to a schedule; the page now streams the live matrix per animation
  frame while the preview owns display and the worker redraws the
  freshest candidate (33 ms throttle). Paused-sim drag: 10/10 fluid-region
  samples change (structurally impossible before).

## Measurement laws (hard-won; do not regress)

- **Whole-screenshot distinct-frame hashing is INVALID on this page** —
  the HUD fps counter ticks every frame and fakes smoothness (this fooled
  a full verification pass; the user caught it). Use
  `scratch/masked-motion-probe.mjs` (fluid-region-only clip hashing +
  canvas visibility inventory).
- `overlay.__sphWorkerOffscreenPresentation` is a mount-time snapshot;
  poll `overlay.__sphScene.getWorkerOffscreenPresentation()` live.
- Bridge counters: `displayOwnerEpoch` churning with
  `contentFrameSerial > 0` and `contentReady:false` means something is
  stealing/blanking the display.
- Read the user's FULL URL before believing a rate collapse
  (`#scenario=custom` + missing runtime keys = degraded config, not
  physics). Physics runs in the viewer's browser on the viewer's GPU.
- One GPU probe at a time; the user's live tab counts as one. Don't edit
  src/ during a probe window (vite HMR invalidates the run).
- 250 ms screenshot sampling saturates at 4/s — all-distinct means "at
  least", never a rate.
